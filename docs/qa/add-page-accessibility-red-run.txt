Limits of the stylesheet reader, found while writing it (jsdom 29 / css-tree; also reported to the orchestrator):
  - Inside ONE rule the CSSOM keeps only the last declaration of a property, so "each token declared once" can only detect a
    duplicate across two :root rules.
  - css-tree drops a rule it cannot parse (for example @property) without a trace, so "throw on an unknown rule type" fires only
    for rule types jsdom builds (@import, @font-face, @namespace, @page are caught and tested).
  - jsdom prints "Could not parse CSS stylesheet" on stderr for some nested rules it nevertheless builds; that cannot be
    captured from a test.
  - jsdom rewrites a colour literal outside custom properties to rgb(r, g, b), so the FR-63 literal regex fires through its
    rgb( alternative; failure messages show rgb(255, 255, 255) where the file says #fff. Token values in :root stay verbatim.
  - jsdom serialises `border: none` as `medium` and `outline: 0` as `0px`; the scan allows `none`, 0, 0px and medium.
  - Lengths are read in px only; a ring written in rem would fail the "at least 2px" check on purpose (reported, not widened).
