## 3. Assumptions and notes (new)

- **A-40:** the setup sheet replaces row 86's FR-87/FR-89 placement by the user's chat decision of 2026-10-09 (summary button plus sheet). Row 86's Q1 default (4×4: control visible, levels 2 to 4 `aria-disabled`, with a reason) survives inside the sheet. **ASSUMPTION: "in the place of the size control in the page order" means FR-68's second position; the human ratifies.**
- **A-41:** the sheet is named by `aria-label` and has no heading element, because the play-page spec allows `id` only to wire the rules popover and the confirmation dialog (spec "Ids" bullet; reconciled for FR-61/A-28: no `for`, no ids elsewhere). The sheet needs exactly **one new id** for `popovertarget` (suffixed with the mount number like the others): ids per mount go from three to **four**, and for two mounts from six to eight. `popover` opening needs that id; no other id is added. Mount-scoped test `tests/play-page-semantics.test.ts` changes deliberately (section 5).
- **A-42:** option descriptions are exposed as text inside the radio button, so the accessible name is name plus description (consistent with FR-62: "labelled by its own visible text", no `aria-labelledby`). The alternative, `aria-describedby` on each option, gives a short name and a separate description but needs four more ids (eight per mount) and reopens the id rule; not recommended (Q2). A screen-reader user hears the whole line, which is at most about 100 characters.
- **A-43:** `aria-haspopup` and `aria-expanded` are **not** set by script. Browsers expose the open state of a `popovertarget` button natively; a script-free open has no code to keep `aria-expanded` in sync, and the «Правила» button does the same today. Real screen-reader output is not tested (A-28). **ASSUMPTION (to confirm, Q6).**
- **A-44:** jsdom does not implement `popover`. Tests install stubs for `showPopover`, `hidePopover`, `togglePopover` and the `toggle` event on `HTMLElement.prototype`, as the existing tests do for `HTMLDialogElement` (play-page spec, "Dialog stubs"); closing by choice needs `hidePopover()` (script). "Opens with no script" is tested by the attributes only (`popovertarget` equals the sheet's id, `popover` present), as for the rules panel.
- FR-69 style (`aria-disabled`) stays for the unavailable levels. The summary button's "▾" cue is the user's.
- Unavailable-level press while the sheet is open: the sheet stays open (the player is choosing); every other press closes it.

## 3a. Row 91: attempt limit and page retry (A-35, A-38 amended; follow-ups)

- **A-35 (amended):** the attempt bound is **100** (was the prototype's 30). Evidence: `docs/qa/add-difficulty-engine/spike.txt`; at 30 attempts 18 of 6000 combinations ran out (15 of them at (6, 2)); the maximum attempts needed over seeds 1 to 1000 is 84; worst time about 51 ms at 6×6 and 113 ms at 8×8. The NFR-2 and NFR-3 bounds are unchanged, and the A-36 margin rule (at most 50% of the bound) still applies and is re-measured with the new limit.
- **A-38 (amended):** a run-out on the page is retried with the next seed the page would take (same seed source; deterministic in tests through the injected seed function), at most 3 seeds for one press. Only if all 3 run out does the old behaviour apply (keep board, messages, size, level; no message text). Consequence for the existing rule "a change takes exactly one seed" (FR-51 area): it holds for every success on the first seed; a retry takes up to 3. Cancelled confirmations, no-ops and unavailable-level presses still take no seed. **ASSUMPTION: only the run-out error is retried; other generator errors are not.**
- **DL1 `openspec/changes/add-difficulty-engine`:** `MAX_ATTEMPTS` 30 becomes 100, and its spec delta, design and tests that pin 30 change deliberately (source: FR-84, row 91). It waits for the signed text before its red tests pin the limit.
- **DL2 `openspec/changes/add-level-selector`:** adds the retry (up to 3 seeds) to the page path (`newPuzzle`), scenarios for retry success on the 2nd and 3rd seed, for 3 run-outs keeping everything, and for a non-run-out error not retried; the seed-count scenarios are adjusted accordingly. Test fixtures use an injected `generate` that throws the run-out error.
