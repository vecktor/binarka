## 3. Assumptions and notes (new)

- **A-48:** a theme or language preference is not game state; TC-12 is amended to say so, and FR-46 (saved progress) stays Future. **ASSUMPTION: a press writes the pressed value even when it is the default (`auto`, `uk`), rather than removing the key; the human ratifies.** The existing spec scenarios "`localStorage` and `sessionStorage` still hold no entry" after a size or level press stay true, because those tests never press a theme or language option (FR-113).
- **A-49:** the page never reads `navigator.language` or `Accept-Language`. It is Ukrainian unless `en` is stored (decision 2: "starts in Ukrainian until the player switches").
- **A-50:** jsdom has no `matchMedia`. Tests install a stub on `window` that returns `{ matches, media, addEventListener, removeEventListener }`, records the `change` listeners and lets the test fire them; it is removed after each test, like the popover stubs (A-44). jsdom has a working `localStorage`; it survives between tests of one file, so every page test clears it before and after (section 6, verification notes). **ASSUMPTION: with no `matchMedia` at all, auto resolves to light.**
- **A-51:** the page has not ported the design's palette yet (the warm palette is G2, row 74) and has no dark theme at all. - **A-52:** the per-mode scan exception rests on the `lang` attribute of each language option (WCAG 3.1.2). A text is skipped only when its element (or an ancestor below the root) carries a `lang` different from `<html lang>`; nothing else is exempt.
- **A-53:** a language switch changes the text of a non-empty `role="status"` region (hint or win), so a screen reader may announce it again in the new language. This is accepted. Real screen-reader output is not tested (A-28).
- **A-54:** the English hint sentences and the English page strings in the appendix are drafts, refined in the English slice with the user confirming the final strings (precedent rows 86 Q6 and 101). - **A-55:** the confirmation dialog is modal (`showModal()`), so a theme or language switch cannot happen while it is open, and no pending action exists during a switch. A switch made inside an open sheet or panel keeps it open. A press on a control outside an open sheet or panel is a click outside it: the browser's `popover="auto"` light dismiss closes it (sibling FR-97(d)), and for the sheet that discards the marked choice (sibling FR-100).
