- [ ] 1.2 In `src/ui/style.css` make the board size-aware without a dependency: declare `--n` (default 6; `.board[data-size="4"] { --n: 4 }`, `[data-size="8"] { --n: 8 }`) and `--cell-max: 48px` on `.board` itself (not on `:root` or `#app`); `grid-template-columns: repeat(var(--n), minmax(0, var(--cell-max)))`; `.cell` gets `aspect-ratio: 1` and `min-width: 0` instead of a fixed width and height; font size per `data-size` (22px, 22px, 18px); no `100vw`; style the select to match the buttons. The 8×8 board must fit a 375 px wide screen.

## 2. Rendering and state

- [ ] 2.1 `showPuzzle(puzzle, n)` first checks that `puzzle.givens` has n rows of n cells and throws otherwise, before touching any state (the caller treats it as a generator failure); then builds `[data-board]` with `data-size = n` and n×n `[data-cell]` elements (`data-row`, `data-col` 1 to n, `data-given`); `renderCell` loops use n (FR-31, FR-43).
- [ ] 2.2 `refreshHighlights` and the whole-line expansion of a `count` violation use `board.length` (the model being checked), never the closure `size`; no digit counting or run checking is added in `src/ui/` (FR-36, FR-38).
- [ ] 2.3 Build the select once at mount, above the board host: `<select data-control="size">` with three `option` elements, values `4`, `6`, `8`, texts «Поле 4×4», «Поле 6×6», «Поле 8×8», option 6 selected; no `aria-label`, `title`, `placeholder`, `alt` or `label` attribute is added (NFR-5).
- [ ] 2.4 `newPuzzle(requestedSize)`, in this order inside the existing try/catch: take one seed from the seed source (a failed attempt still consumed it), call `generate(requestedSize, seed)`, call `showPuzzle(puzzle, requestedSize)` (validates the shape, then replaces model and DOM), and only after it succeeded commit `size = requestedSize` and return true; on any throw keep the previous board, messages, highlights and `size` and return false (FR-42, FR-43).
- [ ] 2.5 `restoreSelect()` sets `selected = true` on the option whose value is `String(size)`; it does not assign `select.value`.

## 3. Interaction (selector, change handler, new puzzle keeps size)

- [ ] 3.1 One `change` listener on the select (added once at mount): accept `select.value` only if it equals `String(n)` for an n in `[4, 6, 8]` (exact string match, not `Number(...)`); otherwise call `restoreSelect()` and return with no seed call, no generate call and no other change (FR-43).
- [ ] 3.2 For an accepted value call `newPuzzle(n)`; on success clear `[data-message="hint"]` and `[data-message="win"]` (highlights follow from the new board); on failure call `restoreSelect()` and keep everything else (FR-43, FR-38, FR-40).
- [ ] 3.3 The new-puzzle button calls `newPuzzle(size)` with the current size, clears both messages on success, and leaves the select as it is (FR-42, FR-43).
- [ ] 3.4 Keep the single delegated click listener on `[data-board]` and the hint button listener unchanged; confirm by reading that nothing in `src/ui/` still uses a literal 6 or 36 for the board.
