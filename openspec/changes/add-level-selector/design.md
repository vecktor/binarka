- Authentication: none exists, so no redirect-to-login or forbidden case applies.

## Key decisions

1. **One `level` beside `size`; one generation path with the retry.** `newPuzzle(size, level)` is the only place that takes a seed and calls `generate(size, seed, level)`: the mount, «Нова головоломка», a size change and a level change go through it. It loops up to 3 times while the engine throws `GenerationRunOutError` (checked with `instanceof`, imported from the engine), taking a new seed each time; any other throw or a result that is not n×n returns false at once (A-38, ratified assumption). Success changes `size`, `level`, the board and the summary together; failure changes nothing. Trade-off: the baseline rule "one seed per change" now holds only on a first-seed success (the delta rewrites the seed requirement and adds scenarios for the 2nd and 3rd seed); the alternative, retrying every error, was rejected by the user.
2. **The sheet is a popover that copies the rules panel mechanism (FR-96).** `popover="auto"`, `role="dialog"`, `aria-label` instead of a heading, so the only new id is the sheet's own (four ids per mount, A-41). The summary button opens it natively with `popovertarget`; the page closes it only by script when a press is made (`hidePopover()`, then `summary.focus()`). Escape, light dismiss and «Закрити» are native and the page adds no key handler (FR-59). Trade-off: opening one popover closes the other (the rules panel); accepted and not specified (FR-93 note).
3. **Focus after a native close comes from the `toggle` event.** The page listens to the sheet's `toggle` and, on `newState === 'closed'` with no confirmation dialog open, focuses the summary button. A browser fires `toggle` asynchronously, after `hidePopover()` and possibly after the dialog was opened and focused on «Скасувати»; the guard "dialog not open" stops the late event from stealing focus. The delta has a scenario for the late event. **Amended after the review-gate fix round (2026-10-09):** a second guard: when DOM focus is already on an element outside the sheet other than the body (a light dismiss by a click on a cell, «Підказка» or «Правила»), the listener leaves it there; this also covers the rules panel, whose «Зрозуміло» has autofocus. Trade-off: one listener and two guards; without them the focus after Escape depends on the browser.
4. **The confirmation order is fixed (FR-98).** For a size or level press that needs the confirmation: `hidePopover()`, then `showModal()`, then `noButton.focus()` (the existing rule). «Скасувати» and Escape end with `summary.focus()`; «Так, почати» performs the change and then `summary.focus()`. The existing pending-action slot `requestAction` is reused, with the sheet closing added to the size and level callers only (not to «Нова головоломка» and «Скинути»).
5. **A size change to 4 forces level 1 inside the same puzzle (FR-92).** `changeSize(4)` calls `newPuzzle(4, 1)`: one confirmation, one seed (more only on a run-out). The level is not restored on the way back to 6 or 8.
6. **Unavailable levels use `aria-disabled="true"`, not `disabled` and not hiding (Q1 option a, FR-91).** A press returns before `requestAction` and does not close the sheet (FR-73, FR-97). The reason is a plain `p[data-level-reason]` as the first child inside the level group (FR-91 "in the level group"; the design reference `review-set-11` puts it first too, so at 4×4 the radiogroup holds one non-radio child plus exactly four radio buttons); in the product it is always in the DOM and carries `hidden` and empty text at 6×6 and 8×8. The design renders it only at 4×4 instead; the product deliberately differs (task 1.4, 2026-10-09: a hidden element renders nothing, so the pixels match, and the DOM stays stable for the tests). The non-colour cue (a dashed border or a struck-through name in the wireframe) is a stylesheet declaration, pinned as "a `border-style` different from the plain rule's, or a `text-decoration` other than none", and confirmed against the designer's iteration before tests are written (task 1.4).
7. **Level option content is two spans with an ordinary space between (FR-99, A-42).** The accessible name is the text content, name then description; no `aria-describedby` (it would need four ids). The descriptions are the user's final text, each at most 80 characters, measured by a test. There is no description line on the page body and no toast (FR-89).
8. **The summary button has three children (FR-95).** A visually hidden prefix span «Поле і складність: », a text span «6×6 · Задачка», and an `aria-hidden` «▾» span. Its accessible name is its text content without the `aria-hidden` child, so the visible text is contained in the name (WCAG 2.5.3). No `aria-label`, `aria-haspopup` or scripted `aria-expanded` (A-43). The visible text is rewritten in one place, after every shown board, and nowhere else.
9. **The page hint passes ceiling 4 (FR-77, Q2).** The engine's `hint(board, ceiling = 1)` keeps the three basic rules by default (autonomy-log row 88, option B; DL1 does not change the page), so the page calls `hint(board, 4)` at every level. Cost: a level-1 player can get a hint no level-1 puzzle needs; accepted by the user. The delta has a scenario that the same board gives the same hint at every level.
10. **Level controls have their own classes and rules.** `.setup-button` (the summary button; its text span is `.setup-summary`, as in the design) and `.level-control button` (plain, `[aria-checked='true']`, `[aria-disabled='true']`) each set `color` and `background-color` from the existing 13 tokens, 4.5:1, no `opacity`. They are not merged into the `.size-control` selector list, because the existing stylesheet tests read the declarations of `.size-control button` by that exact selector.
11. **Rules panel DOM (spec-made proxies).** The rules list is the panel's direct-child `ul`; the techniques section is `div[data-section="techniques"]` with an `h3` «Складніші прийоми» and its own `ul`, between the rules list and the close button; no ids, no examples. FR-93 gives the texts, not the elements; the hook, the `h3` and the order follow the designer's iteration if it differs (task 1.4).
12. **MODIFIED, not ADDED, where a baseline requirement's text would otherwise contradict the new behaviour.** Fifteen blocks. Eleven carry the amended FRs: «New puzzle button» (FR-42), «Reset button» (FR-58), «Rules panel» (FR-57), «Page document order» (FR-68), «Confirmation before discarding player entries» (FR-67), «Pressing the shown size changes nothing» (FR-73), «Grid size selector» (FR-43), «Every cell is its own Tab stop» (FR-59), «Cells and buttons show a visible, unobscured focus indicator» (FR-65), «Hinted cell marker» (FR-66) and the WCAG requirement (NFR-9). Four exist only because a baseline list is closed: «Seed is chosen outside the engine…» (its list of attempts, "at no other time"), «Hint message stays…» (what clears it), «The board is a labelled group…» (the closed list of three ids) and «Highlighting follows every board change» (its list of board changes). The amended FR-62 has no block: the baseline scenarios of «The size radiogroup has an accessible name» still hold with the control inside the sheet (it is in the DOM at mount). A requirement is modified only where its list is closed ("until…", "at no other time", "the three size buttons", "exactly three ids"); open clauses are covered by ADDED scenarios. «Pressing the shown size changes nothing» keeps its name although it now also covers the level (the archive matches MODIFIED by header). «Cell labels», «Ukrainian page text» and «The size radiogroup has an accessible name» stay unmodified: their general clauses and scenarios still hold with the size control inside the sheet (the sheet is in the DOM at mount, so `[data-control="size"]` and its texts are still found).
13. **Reading rule instead of rewriting every scenario.** The ADDED «Setup sheet» says that wherever a scenario says the player presses or chooses a size or level button, the test first opens the sheet through the stubbed `showPopover()`, and that a generator which "throws" throws an ordinary `Error` unless a scenario says run-out. This keeps about thirty baseline scenarios valid as written.

None of these is ADR-worthy: no dependency, no storage, no new module contract. The only cross-slice contracts are DL1's (`generate` third argument, `hint` ceiling, the exported run-out error; ambiguity A).

## Data model

No stored state (TC-12). Page state in `mountPlayPage`: `size` (4, 6, 8) and `level` (1 to 4, start 1), next to `board`, `givens`, `hinted`, `pending`. Derived on every shown board: the summary text, the `aria-checked` of the size and level buttons, the `aria-disabled` of levels 2 to 4 (true exactly when `size === 4`), and the `hidden` state and text of `[data-level-reason]`. `src/ui/strings.ts` gains, as `as const` data: the summary prefix and separator, the sheet label, the close label, the level group name, four names with descriptions, the 4×4 reason, the techniques heading and three items. New DOM: the summary button, the sheet with its two groups, the reason line and the close button, and the techniques section in the rules panel; one new id (the sheet).

## Error handling strategy

- Run-out: retried up to 3 seeds in total (decision 1). After three run-outs nothing changes, no text, no thrown error; at the mount no board is shown (as an ordinary failure at the mount does today).
- Any other generator error, or a result that is not n×n: caught in `newPuzzle`, which returns false; the caller changes nothing (board, messages, `cell-hinted`, size, level, `aria-checked`, summary). The seed was already taken for that attempt, as in the baseline.
- A press on an unavailable level, a cancelled confirmation, Escape and a dismissed sheet: no seed, no generator call, nothing changes (FR-73, FR-67, FR-97).
- Every mutation is a click on a fixed button; no free value, so no validation message is needed and no raw 500 can reach the user. No authentication, so no redirect cases.

## Risks and mitigations

- **DL1's interface differs** (argument order, error class name, the `hint` ceiling parameter, whether the run-out error is exported from the engine index): task 1.3 reads DL1's archived spec first; the delta and this design are edited before any test is written.
- **The designer's iteration differs from the spec-made DOM** (the reason line's place, the `hidden` mechanism, the techniques heading level, the non-colour cue, whether the summary uses a hidden-prefix span): task 1.4 compares; spec-made proxies move, FR texts do not.
- **Late `toggle` events steal focus** (decision 3): guarded and tested; a real-browser check of Escape is in 4.9.
- **jsdom has no popover** (A-44): behaviour that depends on the browser (native open, light dismiss, focus restoration) is covered only by the stubs and by the real-browser check; it is not claimed in jsdom.
- **A level-4 board is slow to generate on a click, and a retry triples the wait** (NFR-2, NFR-3 are DL1's; the page is synchronous): none in this slice; watch it in the browser check (4.9).
- **Strings change after tests are written:** the user's changes go in one step with their source (tasks 1.5, 4.8).
- **The loose seed regex of «Seed is not shown»** could match digits in new text: the new texts contain only "4×4", "6×6", "8×8"; the scenario runs with the new controls present.
- **Panel and sheet are both popovers:** opening one closes the other; expected, not specified.
