# Design: reconcile-ux-accessibility

## Goals

- Make the play-page spec, the page code and the tests describe one model: the UX page model (button cells, radiogroup, rules popover, confirmation dialog) with `main`'s accessibility rules that fit it. The signed text is in `docs/requirements.md` (FR-59 to FR-62, FR-65, NFR-9, A-20, A-28) and `docs/handoff/reconcile-amendment-draft-2026-10-09.md`.
- Add only what the signed text needs to the page: `role="group"` and `aria-label` on the board, `aria-invalid` on highlighted cells, `role="status"` on the hint and win messages.
- Keep every test that no changed sentence touches, byte for byte (the user's rule for this change). `tasks.md` section 1 is the audit list.

## Non-goals

- Any change to the frozen design (answer to question 3). A visible «Розмір поля» label (answer to question 1). 44 px targets and puzzle state in the URL (declined, rows 43 and 66). The palette port and pixel parity (G2, NFR-14), browser checks (G1, NFR-10 to NFR-13). Real screen-reader output (A-28).
- Arrow, Home and End keys, a roving `tabindex`, a `<select>`, `aria-readonly`: all dropped by the signed text, none re-expressed.
- Authentication: none exists, so no redirect-to-login or forbidden case. There is no free-text input, so no inline validation message exists to write.

## Key decisions

Status of each decision: 4 and 8 are SIGNED by the user (FR-59, FR-62, FR-63, `docs/requirements.md`, autonomy-log row 79); 3 was confirmed by the user on 2026-10-09 and its strict key handling is signed in FR-59 and FR-60; 6 is signed for the board's children and the cell roles (FR-61); 1, 2, 5, 7 and the NFR-9 and FR-64 remarks of 8 are the spec-writer's choices, for the auditor to check. D1 and D2 are in the next section.

1. **The UX model wins, and the spec is changed by name, not by overlay.** Six `main` requirements carry names that describe the grid (`The board is a single Tab stop`, `…rows and cells have grid roles`, …). They are RENAMED, then MODIFIED under the new name (OpenSpec applies RENAMED, REMOVED, MODIFIED, ADDED in that order, and MODIFIED must use the new header; verified by archiving a scratch copy). Trade-off: more delta text than keeping the old names, but a baseline whose headers lie is a trap for the next reader. **ADR candidate** (not written now): «button cells and a radiogroup instead of the APG grid», with the reasons of row 77 (the frozen design has no row elements) and the cost (no arrow-key navigation, A-24).
2. **Arrow, Home and End: REMOVE the requirement, state the absence in FR-59.** The alternative was to keep «Arrow, Home and End keys move the focus» as a requirement that says "does not". A requirement named after a behaviour cannot hold its negation, and FR-59 would have two owners. So the keys requirement is REMOVED (with Reason and Migration), and «Every cell is its own Tab stop» says, next to "no `tabindex`", that no key on the board is handled or prevented. One owner per FR; the "not handled" statement is checkable (`defaultPrevented` false, focus and cells unchanged).
3. **Enter and Space are the browser's, and the tests do not pretend otherwise.** FR-69's existing text already says the page does not re-implement them and jsdom does not turn a key press into a click. The page gets no key handler. FR-60 is therefore tested as: (a) the cell is a `button` (FR-69 tests, untouched); (b) the page does not handle or prevent Enter and Space (a `keydown`/`keyup` alone changes nothing and is not prevented); (c) a click cycles and the cell keeps the focus; (d) a given changes nothing. The draft's table says «Enter/Space kept»; in jsdom a key-driven cycling test cannot be kept, because there is no handler to cycle it. Alternative, not chosen: a helper that dispatches `keydown`, `keyup` and then `click()`; it keeps the old test titles but tests only the click, and it hides the one real risk (a future key handler that double-cycles). The user confirmed this test shape on 2026-10-09, and FR-60 now says «The page SHALL NOT handle key events on a cell; activation is the native button's». Consequence: the baseline scenario «Highlight appears immediately after Enter or Space» (a `keydown` that cycles a cell) is deleted, and FR-38's key path is covered only by the browser step 5.4a. The real keys are checked in the browser, `tasks.md` 5.4 (an explicit Enter/Space sub-step with evidence), and by the held NFR-13.
4. **Two focus sentences: SIGNED (FR-59, row 79).** «Showing a board (at mount, after a new puzzle, a size change or a reset) never moves the focus, and a hint leaves the focus on the hint button» lived in `main`'s Tab-stop requirement and are now in the signed FR-59. «Every cell is its own Tab stop» carries them (the reset is added to the list), and their tests stay (rewritten only where they asserted a Tab stop). «A click moves the Tab stop» is dropped, not re-expressed, as signed.
5. **Scope of the delta is found by grep, not by the appended block.** `main`'s model also leaked into four UX-side requirements that the signed text contradicts or overlaps: «Given cells are locked» (a click on a given moves the Tab stop; keys are prevented), «Highlighting follows every board change» (a scenario dispatches `keydown` to cycle), «Ukrainian page text» (the cell-name pattern «…: порожня»), «Cells are buttons» (its last sentence says arrow keys are «not specified», FR-59 now says they are not handled). They are MODIFIED, with the least text changed; the highlighting scenario that dispatches `keydown` is deleted because a key press cannot cycle a cell in jsdom (decision 3).
6. **FR-61: the FR-70 label wins; `aria-disabled` replaces `aria-readonly`; `aria-invalid` stays** (signed, with the answer to question 2). The cells are direct children of the board, as in the frozen design. The sentence «no `display: contents`» stays, reworded: the reason (dropped row semantics) is gone, but the same browser bug hits a group and its buttons.
7. **Ids.** The page already builds `rules-panel-N`, `rules-title-N` and `confirm-text-N` from one module counter. The spec now says exactly that: three ids, each ending in a number of the mount, no other `id`, no `for`. The test counts the three elements instead of asserting zero ids.
8. **FR-62, FR-63, FR-64 (the FR-62 and FR-63 parts are SIGNED, row 79).** FR-62 is an `aria-label` on the radiogroup and the buttons' own text, with no `aria-label` or `aria-labelledby` on a button, no `label`, no `select`, and no text of the page showing «Розмір поля». FR-63 keeps `role="status"`, gives the idle line no role, and (new) keeps the empty hint and win regions rendered, not `display: none`, so the first message is announced; today `.message:empty { display: none }` breaks that, and task 3.6a gives an empty region zero height and margin instead. FR-64 needs no delta: the requirement and its tests are about the `cell-*` classes and the computed border, which are the same on a button, and the stylesheet ones already pass (red run; the DOM test sem-17 goes green with `aria-invalid`); the draft's «selectors only» row turned out to be empty. NFR-9 follows the signed list, so WCAG 2.4.11 is no longer named; the rule that the ring is not covered by neighbours stays in the FR-65 focus requirement.

## Decisions taken by the user (2026-10-09, in chat)

The signed text was silent on two collisions between the UX stylesheet and `main`'s stylesheet rules; both showed in the red run as failing stylesheet tests that no signed sentence changes. The user decided both, and the FR-60 test shape (decision 3 above). They no longer block the archive.

**D1. `:has()`: option (1), decided by the user.** The idle line is "visible only while hint and win are empty, by CSS only" (FR-71) and the document order is fixed by FR-68 (idle, hint, win), so only `.messages:has(…) .message-idle` can do it. The ban on `:has(` (the baseline focus requirement, `docs/frontend-conventions.md` rule 20) is lifted for that one selector, and the exception is now in the signed FR-65 row («uses `:has(` in exactly one rule, the one that hides the idle line (FR-71)»). The delta pins it harder than the row: the rule's subject is `.message-idle` and its only declaration is `display: none`. The delta now says so: «The stylesheet SHALL NOT contain `!important`, and SHALL NOT contain `:has(` except in the one selector that hides the idle line: exactly one rule contains `:has(`, the subject of its selector is `.message-idle`, and it declares nothing but `display: none`», and the scenario «The stylesheet stays inside the build target, with one `:has(` exception» pins it. Cost: in Firefox 114 to 120 the idle line stays visible next to a message (cosmetic; popover and dialog already need newer browsers than rule 20's target, A-14). Effects: test ss-19 is rewritten (R), rule 20 of `docs/frontend-conventions.md` gets a row for this exception (task 3.9), no change to `src/ui/style.css` for `:has` (task 3.8 checks it).

**D2. Colour literals: option (A), decided by the user.** FR-65's scan (every colour is a `var(--color-…)`, 13 tokens) is unchanged; no spec change. The UX stylesheet has about 24 declarations with literals, mapped onto the existing 13 tokens: `#fff` and the unchecked size button's `background: transparent` → `--color-control-bg` (the wrapper is already white, so no visible change); `#1f2937` and the size buttons' `#4b5563` text → `--color-text`; `#9ca3af`, `#6b7280` → `--color-control-border`; `#2563eb` → `--color-focus`; the hinted cell's `#4b5563` dashed border → `--color-given-border`; `#d1d5db`, `#e5e7eb`, `#dbeafe` → `--color-given-bg`; `#f9fafb` → `--color-page`; the `rgba()` backdrops → `background-color: var(--color-text)` with `opacity` (.45 and .3); borders written as longhands (`border-color: transparent` where needed). Accepted cost: a small drift from the frozen look (for example the checked size button is grey with a blue border, not light blue) until G2 ports the palette (G2 owns the palette and keeps the FR-65 test green). Task 3.7 does the mapping; task 5.2 takes screenshots that show the drift.

## Data model

No new state. DOM attributes added by the page: `role="group"`, `aria-label` (board); `aria-invalid="true"` (set and removed in `refreshHighlights`, absent rather than `"false"`); `role="status"` (hint and win). One stylesheet rule changes for FR-63: an empty message region gets zero height and margin instead of `display: none`. `src/ui/strings.ts` is unchanged (`sizeLabel(n)` already gives «Поле N×N»). `src/ui/grid.ts` is deleted: nothing imports it, and it holds Cyrillic outside `strings.ts` (the two source-scan tests fail on it).

## Error handling strategy

Unchanged: a generator failure keeps the previous board (FR-43); nothing new can fail. A key event is never prevented, so no keyboard trap exists. There is no input to validate.

## Risks and mitigations

- **Silent weakening of tests.** Many tests are removed. Mitigation: each one is listed in `tasks.md` with the changed sentence it follows from; the rewritten ones keep their assertions about unchanged behaviour (names, `aria-invalid`, focus); every other test is untouched and must be green in the same run.
- **A rewritten test passes at once** (the UX page already has no `tabindex`, no key handler). Mitigation: the red run lists them as «green at start, regression guard»; the red tests are the FR-61, FR-63, NFR-9 and stylesheet ones.
- **Visual drift from D2 (option A, decided).** Mitigation: screenshots at 375 and 1280 px in 5.1 and 5.2, a note in `docs/current-state.md` that G2 owns the palette.
- **jsdom hides what matters** (real Tab order, real Enter/Space, focus rings, layout). Mitigation: section 5 is a real-browser check with screenshots; it is a gate for the archive and is not ticked without its evidence. The held NFR-13 stays the automated check.
- **`add-logo` (active, not implemented)** builds an inline SVG. If it ever puts an `id` on a `<defs>` child or a gradient, the rule «exactly three ids» in the FR-61 requirement and its tests break; that change must avoid ids (or amend the rule) when it is implemented.
