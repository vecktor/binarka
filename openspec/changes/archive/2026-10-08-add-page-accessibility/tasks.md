# Tasks: add-page-accessibility

Order of work (the per-slice loop). Section 5 (tests) is written FIRST from the delta spec
and seen red before sections 1 (CSS), 2, 3 and 4 are implemented; sections are numbered by
area, not by time. No database exists, so the DB smoke flow of the template maps to the
keyboard check in 6.10. Commits carry `Slice: add-page-accessibility` and `Refs: FR-57`
(plus the other FR or NFR ids the commit touches).

1. The change folder is committed alone (1.1).
2. The test-engineer writes section 5 and runs it red; the failures are assertion failures,
   not missing modules; the evidence goes to `docs/qa/add-page-accessibility-red-run.txt` (5.11).
3. The capability-implementer does sections 1 to 4, inside `src/ui/` only (and `index.html`
   only if needed; none is expected). Tests never import `src/ui/grid.ts` directly, so no
   red test fails on a missing module and no stub exists in `src/` at the red stage.
4. The full battery: lint, tests, build, strict validation (6.1 to 6.6).
5. A keyboard check in the built-in browser, the TC-13 smoke (6.10).
6. The per-slice review with a clean `review-findings.json` (6.8).
7. Archive, with `Slice: add-page-accessibility` commits (6.11).
