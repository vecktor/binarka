# Design: update-page-layout-geometry

## Context

G2 block 1 (autonomy-log row 148). The page and the design share the markup of the main column (`.page-header`, `.setup-button`, `.board-host`, `.board`, `.cell`, `.buttons`, `.messages` and the `data-*` contract), so the design's layout rules port almost verbatim.

## Decisions

1. **Port the formulas, do not re-derive.** The design's sizes are formulas (`--column`, `--cell-max` with `clamp(…dvh…)`, `--board-width`, the cell digit from `100cqi`). The fixture holds the fractional results (for example a 35.25 px 8×8 cell at 320), and they only match if the formula is the same.
2. **Geometry only.** Ported: `box-sizing`, `display`, `position` (the empty messages), flex and grid (including `flex`, `flex-basis`, `flex-grow`, `justify-content`, `align-items`), `width`/`height`/`min-*`/`max-*`, `margin` (including `margin-block`, `margin-inline`), `padding`, `gap`, `border-width` and `border-style`, `border-radius`, `font-size`, `font-weight`, `font-variant-numeric`, `line-height`, `letter-spacing`, `aspect-ratio`, `container-type`, and the text layout that decides line breaks and widths (`text-align`, `white-space`, `overflow` with `text-overflow`, `text-wrap: balance`). Also ported, as rendering rather than colour: `-webkit-font-smoothing: antialiased` and `text-size-adjust: 100%` (they change how text is drawn, as in the reference) and `body { min-height: 100vh }`. The given cell's weight and the cells' cue borders (given 2px, violation 3px, hinted dashed) stay as they are: they are cues (FR-64, FR-65) and do not change a cell's box, which the grid sets. Not ported: colours, backgrounds, shadows, backdrops, text decoration and hover/active feedback. Borders take their colour from an existing token (`--color-cell-border`, `--color-control-border`, `--color-given-border`, `--color-focus`), or the `transparent` keyword where the design's border is a frame that the palette block fills (the board, the message lines); the FR-65 colour scan allows that keyword.
3. **Token names are kept.** The 13 `--color-*` tokens of A-51 keep their names and values. The new layout variables (`--space-*`, `--radius-*`, `--page-pad`, `--page-max`, `--column`, `--reserve`, `--board-gap-6`, `--board-pad-6` on `#app`; `--n`, `--cell-max`, `--board-gap`, `--board-pad`, `--board-width`, `--bleed` on the board; `--gap`; `--message-*`) are not colour tokens; the stylesheet helpers resolve only `--color-*`. The column formula reads the 6×6 board's gap and padding from `--board-gap-6` and `--board-pad-6`, the same variables the board's default uses, so the two cannot drift apart (review run 1).
4. **The win state keeps its geometry.** After a win the new-puzzle button takes the bold weight from the hint button (geometry: the text widths). The design's solved board also adds a 1 px ring as a box shadow, which is paint, not geometry; it comes with the palette block.
5. **No has-selector outside the idle line.** The design reads the board size and the solved state with `:has()`, which the build target does not allow outside the idle-line rule (FR-65, A-14; the user's decision D1, autonomy-log row 79). The size-dependent variables are declared on `.board[data-size]` itself, the 8×8 bleed on phones moves onto the board (negative inline margins, the same boxes), and the board host carries `data-solved="true"` while the board is solved (set by the page with the win line), read by a sibling selector for the button weights.
6. **Empty messages stay rendered.** The design hides an empty hint or win line with `display: none`; FR-63 keeps them rendered as live regions. They leave the flow instead (`position: absolute`, no padding or border, so 0×0), which takes no gap; the hint's 4px accent applies only to a shown hint (`:not(:empty)`), so an empty hint is 0×0 too (review run 1). The geometry test treats two 0×0 boxes as matching wherever they are: they paint nothing. Both lines are among the fixture's elements.
7. **The settings panel moves with the column.** Its 48rem placement was written against the 420 px column (`calc(50% + 210px - 22rem)`); the design's placement (`width: min(22rem, var(--column))`, top 6rem, right edge on the column's right edge) is ported, so the panel stays under the header.

## Instruments

- **Geometry (the gate of this block):** `e2e/nfr-14-layout-geometry.spec.ts` against `quality/design-geometry.json`, tolerance 0.5 px. Sampling dimension: viewport and state. Sample points: the 32 light reference shots of the states default (6 viewports), four, eight, level, win and hint (eight at 6, the others at 5); the hint case presses «Підказка» once after load. Plus the settings placement at the four viewports from 48rem and the setup sheet's levels at 1366×650. Coverage: `sampled`.
- **Cross-check:** `scripts/visual-block.mjs --block layout` (real device scale, the gate's own capture for pixels), with the same 16 elements and the same 0×0 rule: geometry off 0, unpaired 0 on the states reached at mount (the hint state is checked by the e2e test only, because the tool has no state drivers).
- **Stricter instrument before a definition-of-done is claimed:** a 1 px width sweep (320 to 1440 px) of the same boxes against the design build at the default state (README escalation step 2). Pixel scores stay telemetry for this block; the per-block pixel floor is claimed after the palette block.

## Side effects outside the main column (deliberate, measured)

- `box-sizing: border-box` and the body's line height 1.5 apply to every element, so the setup sheet, the rules panel, the settings panel and the dialog change too. Their own geometry is later blocks.
- **The sheet's level group** `margin-bottom` goes from 24px to 28px: with border-box the footer buttons' 2px borders sit inside their 44 px, and the NFR-13 sheet-footer focus check was red at 4 viewports by up to 1.8 px (`docs/qa/update-page-layout-geometry/nfr-13-red-after-port.txt`).
- **The setup sheet keeps the browser's normal line height** until its own block. As first committed (`b883f36`) the body's 1.5 reached the sheet: the fourth level slid under the sticky footer at 1366×650 (it showed fully before block 1) and at 375 px the sheet grew about 95 px over the board; the setup shots fell (run 4 → run 5: 375-light-setup 0.8087 → 0.7240, 375-light-setup-marked 0.8039 → 0.7291, 375-light-setup-four 0.8273 → 0.7846, 375-light-setup-marked-four 0.8292 → 0.7849). Found by review run 1 and its vision judge; fix round 1 sets `line-height: normal` on `.setup-sheet` (stills `docs/qa/update-page-layout-geometry/fix-round-1-sheet.txt`); run 6 puts the setup shots above run 4 (0.8254, 0.8214, 0.8445, 0.8439). The e2e test «The setup sheet keeps its levels in view at 1366×650» guards it (red without the fix: `review-2-sheet-guard-red.txt`). Known and left for the sheet block (review run 2): at 1366×650 the dimmed idle line of the page shows half-clipped just under the sheet's bottom edge, because the column moved the idle line down; the sheet's top edge already crossed the title before this change. The design's level descriptions are indented to the title column; the page's are not (a gap from before this change, the sheet block).

## Risks

- `line-height: 1.5` on the body and `box-sizing: border-box` change every text and box on the page, including the sheet, the panels and the dialog. NFR-10, NFR-12 and NFR-13 run right after the port, not at the end.
- The 8×8 board bleeds into the page padding on phones. The design widens `.board-host` with `--bleed` (read with a has-selector); here the bleed sits on `.board[data-size='8']` itself (negative inline margins and a width of `min(100% + 2 × bleed, board width)`), which gives the same boxes (decision 5).
- Run 5 of `check:visual` may barely move or dip on some shots (colours dominate; the panels move with the box model). That is expected and is reported as such.
