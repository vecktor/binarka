### Files that matter

- **`app/binarka.css`** is the design: plain CSS keyed on our classes and data attributes, with tokens as CSS custom properties and a dark theme via `prefers-color-scheme`. This is the file to port to `src/ui/style.css`.
- **`components/binarka-page.tsx`** renders the target DOM: size radiogroup, `<button>` cells with Ukrainian `aria-label`s, the message area under the board, the buttons, rules in a closed `<details>`, the confirm `<dialog>`, and the inline SVG logo.
- **`lib/boards.ts`** holds the fixed boards. They match the prompt, and our engine checked the default board and the `/hint` board.

### Review notes (agent, 2026-10-05, read-only: nothing installed or run)

Matches the prompt:
- The DOM structure, classes, data attributes and Ukrainian texts are as specified.
- All styling is in one plain CSS file; no Tailwind on the elements.
- Violations have a second cue (stripes and underline), and the hinted cell has one too (dashed border and italic).
- Focus styles everywhere; the size picker is a segmented radiogroup; the rules are collapsed by default.
- The win state is shown through `data-solved`.

Open points (questions sent to v0, see below):
1. **External font.** `binarka.css` imports Rubik from Google Fonts. That is a network call at runtime (TC-11 says no network calls), and font-load timing makes pixel captures non-deterministic (the capture-determinism lesson in `AGENTS.md`). Options: self-hosted font files, or system fonts.
2. **Template leftovers.** Unused dependencies (`shadcn`, `@base-ui/react`, `lucide-react`, `@vercel/analytics`, Tailwind and `tw-animate-css`), plus `app/globals.css`, `components/ui/button.tsx`, `lib/utils.ts` and the `public/placeholder-*` files, none of them imported by the pages.
3. **`next.config.mjs` sets `typescript.ignoreBuildErrors: true`**, which hides type errors.
4. **Serving the reference** needs pnpm and Next.js. A static export (`output: 'export'`) would let us serve plain HTML from a local folder with no Node server.
5. **For us, not v0:** the logo's SVG `<text>«БІНАРКА»` becomes part of the `<h1>` text content («БІНАРКАБінарка»), even with `aria-hidden`. Our page-text tests read element text, so when porting, either draw the logo word as paths or adjust the heading test deliberately in the amendment.
